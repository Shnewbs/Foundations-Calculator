# Foundations Calculator 0.0.2a.R1 — final 2a acceptance

R1 is the feature-frozen finalization candidate for the 0.0.2a line. Do not add new gameplay systems during this gate; only fix failures found here.

## 1. Automated release gate

Run `VALIDATE_0_0_2a_R1.bat`. The default run must complete a clean build, JUnit, at least **120** standalone GameTests, the optional-integration/KubeJS GameTests, and `tools/check_release.py`. Preserve `validation/0.0.2a.R1/`.

## 2. R9 / pre-R1 migration

Use a copy of a world that already contains Calculator machines and powered items. Existing FE values must survive. No registry IDs or recipe IDs changed.

Raise `energy.machineCapacityMultiplier`, store more than 2,147,483,647 FE, save and reload, and confirm the exact long value survives. Lower capacity below the stored value, save/reload again, and confirm the excess is **preserved**, cannot receive more energy, and drains normally until it returns below capacity. Repeat with an Energy Module and with a Flawless Calculator containing an Energy Module.

## 3. Power interoperability

Test FE plus every integration installed in the pack: GregTech EU, Mekanism J, Modern Industrialization EU, GrandPower and AE2 item charging. Confirm configured ratios/losses/directions, GT voltage/amp refusal, item charge/discharge and side gates. Native long routes must expose full buffers where the external API allows it; the ordinary NeoForge FE facade remains int-bounded per call.

Put a Calculator Screen against a Calculator machine holding more than 2.147B FE and confirm the screen reports the full stored/capacity values rather than an int-saturated value. Place two very large Power Cubes together and confirm automatic equalization converges without bouncing or overflowing.

## 4. Presets and configuration

With `balance.applyPreset=false`, verify R9-equivalent explicit capacities, transfer rates and process costs. Then smoke-test Classic, Balanced, Expert and High Power independently. `/foundations config`, `/foundations config presets`, `/foundations config machine <id>` and `/foundations power` must report effective values without mutating config.

## 5. Field Guide

At the same GUI scale used for the PL4 comparison, confirm the Calculator guide stays near its intended 640x360 desktop footprint, centers correctly, keeps both pages readable and scrollable, and remains usable in a narrow/windowed client. Check Welcome, First 10 Minutes, search, chapter tabs, bookmarks, recipe links, server snapshots, the long-buffer entry, Patchouli mirror and master-reader fallback. The soft-grey guide item must remain the single Calculator guide item.

## 6. Survival progression

Play the real route from the first Calculator through power, dirty-chip restoration/reassembly/analysis, Research Chamber, modules, automation and at least one greenhouse. Verify blocked outputs, insufficient power, side controls, dismantling, save/reload and recipe viewers. Static graph validation of the 910 recipes does not replace this playthrough.

## 7. Performance / soak

Run a large mixed machine network with automation, long buffers and several power adapters. Compare tick behavior to R9. Leave it running, unload/reload chunks, save/restart, and verify no energy duplication/loss, runaway packet traffic or obvious allocation/tick regression.

## Final pass condition

Freeze **0.0.2a.R1** only when the automated gate passes and every section above passes in-game. If it passes, this becomes the final 2a baseline and new feature work moves to the next alpha.
