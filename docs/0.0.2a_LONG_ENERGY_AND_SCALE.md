# Foundations Calculator 0.0.2a — Long energy, scale and integration pass

## Scope

0.0.2a is one coordinated update on top of the R9 Field Guide baseline. It deliberately keeps the 910 recipe files, registry IDs and R9 visual guide work while expanding energy scale, addon APIs, pack administration and validation.

## Long-valued canonical FE

Machine `StoredEnergy` is now a 64-bit store. NeoForge `IEnergyStorage` remains available and intentionally saturates its reported amount/capacity to `Integer.MAX_VALUE`, because that API is int-valued. Native long-valued integrations and the Foundations long-energy API use the full underlying amount.

Machine save data still uses the `Energy` key, now written as a long. Minecraft NBT numeric reads allow old int-valued R9 saves to load through the same key. Capacity reductions still clamp loaded energy to the current effective capacity.

Powered Calculator/module items add the `foundations_calculator:energy_long` data component. The older `energy` int component remains and is updated with a saturated value so old tooling/downgrades can still see a bounded amount. 0.0.2a code always prefers the long component when present.

## Capacity and transfer scale

New server controls:

- `energy.machineCapacityMultiplier`
- `energy.itemCapacityMultiplier`
- `energy.transferMultiplier`
- `machine.<id>.capacityMultiplier` for every configured machine capacity
- `module.<id>.capacityMultiplier` for every configured powered item/module capacity

Multipliers do not alter EU/J/FE exchange ratios. Transfer/charge limits remain int-sized per operation where the underlying API is int-valued.

## Optional balance presets

Presets are disabled by default. `balance.applyPreset=false` preserves explicit R9 behavior.

When enabled, `balance.preset` selects:

- `1` Classic — 1x timing, energy, capacity and transfer
- `2` Balanced — 2x capacity/transfer, 0.85x process energy, 0.90x process time
- `3` Expert — 0.75x capacity/transfer, 1.50x process energy, 1.15x process time
- `4` High Power — 16x capacity, 8x transfer, 0.75x process time

`0` remains Custom/R9 and adds no preset factor.

## Energy display

Client config `information.energyUnit` supports `AUTO`, `FE`, `GT_EU`, `MEKANISM_J`, and `MI_EU`. Explicit server conversion overrides can be displayed in the requested native unit. If that system is inheriting an upstream ratio, Calculator displays FE rather than fabricating a ratio on the client.

## Public API

`com.foundations.calculator.api.LongEnergyStorage` is the unit-safe long-valued canonical-FE contract for addons. `FoundationsEnergy.longItem`, `.longBlock`, route variants, and long adapter registration points are available alongside the existing `IEnergyStorage` API.

Existing FE adapters remain valid. Addons that need buffers above the FE int ceiling should implement the long contract and continue honoring simulation, sided permissions and capacity.

## Operator visibility

Read-only commands:

```text
/foundations config
/foundations config presets
/foundations config machine <id>
```

They summarize effective scale/preset/machine settings without mutating configuration files.

## Progression

`tools/validate_progression.py` parses all Calculator recipe JSON and performs a bounded static reachability check. Vanilla/foreign items and tags are treated as externally obtainable; research, worldgen, loot and player behavior are not simulated. This is a structural guard, not a survival playthrough.
