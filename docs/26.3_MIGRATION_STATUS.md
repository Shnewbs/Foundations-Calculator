# Minecraft 26.3 migration status

Current branch: `port/26.3`. This is experimental source, not a released or loadable mod.

Validated platform boundary: `platform/26.3/.../TransactionalEnergyStorage.java` compiles against real NeoForge 26.3.0.52-beta APIs on Java 25. Its eight JUnit tests pass with zero failures/errors/skips: root commit and rollback, nested transactions, values above the int limit, live transfer limits, reduced capacity, overflow and disabled gates. The standard EnergyHandler operations remain int-valued; native operations and stored amounts are long-valued. It is not yet wired into machines or item capabilities.

Identifiers and GUI extraction type names have been migrated in the branch. The build uses standard runtimeOnly for the Guide API because the 26.3 toolchain removed additionalRuntimeClasspath.

The full compile at f4a7d4fba47c2456dfca52f8783a9019bf028091 failed with 861 compiler diagnostics. Many are cascading consequences of removed APIs, not 861 independent defects. Required work includes:

- Replace old IEnergyStorage, ItemStackHandler and IItemHandler capability boundaries with transaction-aware EnergyHandler and ResourceHandler adapters, including menu slots and item access.
- Migrate block/item registration properties and constructors, recipes and serializers.
- Migrate persistent block state to ValueInput/ValueOutput and NBT Optional/default getters, retaining old saved keys and long amounts.
- Update screens, render state extraction, block entity/item renderers and client input.
- Migrate networking, world interactions, recipe lookup and platform events.
- Replace optional integration coordinates only after verifying actual 26.3 releases; existing 1.21.1 coordinates in this diagnostic branch are not runtime compatibility evidence.
- Compile and run the full native/integration and client/migration acceptance suites before adding a 26.3 binary to a GitHub release.

Evidence:
- Boundary tests and full initial API inventory: https://github.com/Shnewbs/Foundations-Calculator/actions/runs/37511884251
- Identifier/GUI rename compile inventory: https://github.com/Shnewbs/Foundations-Calculator/actions/runs/37512151377

Minecraft 26.4 compatibility is unverified. The isolated platform boundary is preparation, not a compatibility claim.

## Continued migration

The NBT default-getter migration reduced full-compile diagnostics from 861 to 653; preserving historical four-int ownership/research UUID tags reduced them to 638. These are cascading compiler diagnostics, not an estimate of remaining independent defects.

SidedEnergyHandler now gives directional faces live gates and transfer limits over one canonical transaction journal. Three new regression tests cover rollback across multiple faces, commit-only notifications, live policy changes and rates above the int range. These new tests require fresh CI validation; the adapter remains unwired to machine capabilities.

The 1.21.1 CurseForge publisher targets project 1734096. No 26.3 file is uploaded until its platform-specific build and runtime evidence exist.

## R2 canonical capability integration

StoredEnergy now owns the shared snapshot journal used by machine faces and native convenience calls. Boolean execute/simulate helpers open nested transactions when called inside an external root; rollback restores the same canonical machine amount and dirty notifications wait for root commit. Persistence cannot overwrite an active journal.

Machine registration now exposes Capabilities.Energy.BLOCK. Item registration uses Capabilities.Energy.ITEM and ItemAccess exchange of a modified copy, preserving module/component data under transaction rollback. Old int convenience APIs live behind the internal EnergyPort interface instead of removed NeoForge IEnergyStorage. Four new canonical boundary tests exercise these real production classes. Item-access behavior still needs full runtime acceptance.

Inventory ResourceHandler migration, recipe/save/client APIs and platform-specific integration updates remain unfinished. The full native mod must compile and pass runtime checks before a 26.3 release is published.

## GUI, cooldown and interaction-result renames (commit after 26a9841)

Using the CI diagnostics channel's `errors.txt` at `26a9841`, the client screens, menus, several content items and `PowerDiagnostics`/`TransferPayload` were migrated to the real 26.3 renames it reported: `GuiGraphicsExtractor.drawString(...)` to `.text(...)`, `Player.displayClientMessage(Component,boolean)` to `.sendOverlayMessage(Component)`/`.sendSystemMessage(Component)`, `InteractionResult.sidedSuccess(boolean)` to the `InteractionResult.SUCCESS` constant, `ItemCooldowns.addCooldown(Item,int)` to `.addCooldown(ItemStack,int)`, and `BlockPos.getCenter()`/`Entity.getCenter()` to `Vec3.atCenterOf(BlockPos)`. These 24 files were not recompiled locally (no 26.3 toolchain outside CI); the next CI run on this push is the first real check of them.

This pass did not touch `Content.java` (118 of the 571 errors): its tool items (`SwordItem`, `PickaxeItem`, `AxeItem`, `ShovelItem`, `HoeItem`) no longer exist as classes — 26.3 builds tools as plain `Item` configured through `Item.Properties.sword/pickaxe/axe/hoe/shovel(ToolMaterial, float, float)` — and `CalculatorTier` currently implements the old `Tier` interface, which may also be gone. Rewriting `Content.java`'s ~40 tool registrations and `FireSwordItem`'s `hurtEnemy` override correctly needs the real `ToolMaterial` and `Item`/`Weapon`/`Tool` component shapes, not a guess from the old 1.21.1 API. The entity-type builder calls for `ThrownMaterialEntity`/`GrenadeEntity`/the grenade projectiles also fail their generic bound (`EntityType.Builder.of` presumably takes a narrower bound now), `BlockEntityType.Builder` and the `RecipeSerializer` registration overload are both gone in their old forms, and the sapling `TreeGrower` calls reference `Registries.CONFIGURED_FEATURE`, which the probe confirms no longer exists under that name.

`tools/api_probe_queries.txt` now has a "Round 2" section querying exactly these: `ToolMaterial`, `Tier`, `Weapon`/`Tool` components, `DataComponents.UNBREAKABLE`, the relevant `Item` combat hooks, `EntityType.Builder`, `DeferredRegister`'s nested registrars, `RecipeSerializer`, `TreeGrower`, `BlockBehaviour.Properties.isViewBlocking`, and the `StacksResourceHandler`/`ItemAccess` base classes the inventory `ResourceHandler` rewrite needs. Read the next `api-probe.txt` on `ci/port-26.3-diagnostics` before writing any of this; do not guess these signatures.

## CI diagnostics channel

Every push to `port/26.3` now force-pushes a condensed compile report to the `ci/port-26.3-diagnostics` branch, so compiler output can be read with git when run logs and artifacts are unavailable. Fetch it with `git fetch origin ci/port-26.3-diagnostics`. It holds `SUMMARY.md` (error totals, most common failures, missing packages, per-directory and per-file counts), `errors.txt` (every diagnostic in full) and `compile-tail.txt` (the end of the raw Gradle log, for failures that are not javac errors). The report is generated by `tools/ci_condense_javac.py`. The job still fails when the boundary tests or the compile fail.
