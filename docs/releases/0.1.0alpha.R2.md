# Foundations Calculator — alpha R2

This update reduces temporary recipe-matching objects while preserving gameplay
rules and the existing R1 schedule. No recipe data, costs, machine durations,
random-output calls, scan cadence, routing rules or progression settings changed.

- Multi-ingredient allocation uses one flat residual graph rather than an array
  object per graph row. Breadth-first edge order and exact slot consumption stay
  the same, including overlapping tags and repeated ingredients.
- Recipe count extraction and enabled-item checks use direct loops rather than
  constructing stream pipelines, preserving order and short-circuit behavior.
- Process input lists are allocated at their known size, avoiding list growth.

## Comparison with R1

`tools/benchmark_allocator.py --baseline 16de6fb8fb50b0e095adeecb0f8a4b36684afcd0`
compared 100,000 randomized allocations for identical used-slot arrays (including
null failures). Every tenth case sampled inventories up to 63 slots and up to
14 ingredients. No difference was found. The existing exhaustive-assignment
oracle and a new player-sized inventory test cover feasibility and conservation.

On the same local JDK 21.0.9, the mixed allocator microbenchmark allocated
**89.6 bytes/call in R1 and 65.6 in R2: 26.8% less**. Median elapsed time was
62.5 versus 30.1 ns/call on this host; that timing is not a whole-world TPS/FPS
claim. The benchmark does not include recipe callers' count-array/stream objects.
Raw evidence: [allocator R2 vs R1](../performance/allocator-r2-vs-r1.json).
